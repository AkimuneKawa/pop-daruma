# 引き継ぎ書：ポップだるま堂 繁盛記

Claude（claude.ai）で作ったブラウザゲームを、ローカルの Claude Code で開発を続けるための引き継ぎ資料です。
この文書と `pop-daruma.html` をリポジトリ直下に置き、Claude Code に「HANDOFF.md を読んでから作業して」と伝えてください。

---

## 1. ゲーム概要

- **ジャンル**：リアルタイム工房経営シミュレーション（スマホ縦画面・1画面完結）
- **舞台**：昭和レトロポップな町のだるま工房
- **目的**：4月1日〜翌3月10日の1年間で総資産を増やし、称号を得ること
- **核となるジレンマ**：
  - 年末ラッシュや特需の波を読んで在庫を積む
  - 素材の相場の上昇と、入金が3日遅れることによる資金ショートの間でバランスを取る

### これまでの主な設計判断（経緯）

1. 最初はターン制で、制作ミニゲームあり（色塗り・顔描きのタイミング式）でした。
2. オーナーの判断で**リアルタイム制**に変更し、**ミニゲームと品質の概念を廃止**して経営要素に特化しました。
3. 操作を単純化しました。**作る色は全職人共通で1色**です（職人ごとの色指定は不採用）。
4. 紙と絵の具を**「素材」1種類に統合**しました。
5. 画像生成モックアップに合わせて**UIを刷新**しました。**スクロールなしで1画面に収まること**が最重要要件です。

## 3. ゲームの仕様

### 時間
- 1日 = 15秒（`DAY_SEC`）、1ヶ月 = 10日、1年 = 120日（`TOTAL`）。
- 速度は 0（停止）／1／2倍 の3段階です。
- タブが非表示になると自動で一時停止してセーブします。

### 生産の流れ（すべて自動）
1. 作る色が「やめる」以外なら、生産速度（個/日）に応じて素材を1つ使い、乾燥棚へ入れます。
2. 3日（`DRY`）で乾くと完成品として倉庫へ移ります。倉庫が満杯なら棚に留まります（「倉庫満杯」表示）。
3. 生産速度は本人2個/日（`SELF_RATE`）に、雇った職人の速度を足したものです。

### 販売
- 色ごとの来客率 λ（個/日）でポアソン的に来客します。
- 在庫があれば販売し、売上は3日後に入金されます。在庫がなければ売り逃しです。
- 需要の求め方：
  - 基本値は `2.4 × 月別倍率 × 日ごとのノイズ(0.7〜1.3)` です。
  - 色の比率は、通常月が あか45%／みどり20%／あお15%／きいろ20% です。
  - 12〜2月は あか70%、他の色が各10% になります。

### 月別需要倍率（`MM`、4月始まり）
`[1.0, 0.8, 0.7, 0.8, 0.9, 0.8, 1.0, 1.3, 4.0, 4.5, 1.8, 1.2]`
（12月・1月が年末ラッシュで、この2ヶ月は販売価格も×1.4）

### 特需イベント（ゲーム開始時にランダム生成）
| 種類 | 回数・時期 | 予告 | 期間 | 効果 |
|---|---|---|---|---|
| テレビ特需 | 3回（22〜38日、42〜56日、102〜112日のいずれか） | 3日前 | 4日 | 指定色の需要+5.5/日、価格×1.5 |
| インバウンド | 2回（6〜18日、62〜70日） | 4日前 | 6日 | あお+2・きいろ+2・みどり+1/日、この3色の価格×1.4 |
| 年末ラッシュ | 固定（80〜99日） | 11月1日にニュース | 20日 | 上記の月別倍率・色比率 |

### 素材の相場
- 素材の基本価格は350円（`MAT`）× 相場倍率 `m` です。
- `m` は毎日、目標値に向かって上昇時+0.2、下降時−0.12ずつ動きます。
- 1日の入荷上限は条件によって変わります。

| 状況 | 目標 m | 入荷上限/日 |
|---|---|---|
| 平常 | 1.0 | 40 |
| 特需の予告中 | 1.3 | 24 |
| 11月後半（74〜79日） | 1.4 | 20 |
| インバウンド中 | 1.6 | 12 |
| 年末ラッシュ | 1.9 | 12 |
| テレビ特需中 | 2.0 | 10 |

### お金
- **初期状態**：所持金20,000円、素材10、完成品あか2。
- **販売価格**：基本1,500円（`BASE`）× 時期・特需の倍率。
- **月末の支払い**（10日ごと）：家賃3,000円＋職人の月給。
- **資金ショート**：払えない場合、所持金を0にしてショート回数+1。職人がいれば翌月は職人の生産速度が半分になります。3回で閉店（ゲームオーバー）です。

### 投資（1タップ購入）
| 項目 | 効果 | 価格 |
|---|---|---|
| 乾燥棚 | +4枠（初期6、最大18） | 8,000／12,000／16,000 |
| 倉庫 | +15（初期20、最大65）。素材と完成品の合計で数える | 5,000／8,000／12,000 |
| 職人タツ | 生産+2.5個/日 | 契約金5,000・月給4,000 |
| 職人ハナ | 生産+1.5個/日 | 契約金5,000・月給4,000 |

### 決算
- **総資産** ＝ 所持金 ＋ 予定収入 ＋ 完成品×600 ＋ 素材×350
- **称号**：40万以上「だるま大名」／20万以上「名工」／8万以上「一人前」／それ未満「見習い」

### バランス検証の結果（自動プレイで確認済み）
- 投資なしで素材を切らさないだけの場合：販売約165個で「一人前」。
- 棚・倉庫・職人に投資し、特需色に合わせて作った場合：販売約310個で「名工」。
- 「だるま大名」は、年末に向けた備蓄と特需の読みまで決めた上級者向けの想定です。

## 4. UI仕様（スマホ縦・スクロールなし）

画面構成は上から順に次のとおりです。

1. **ヘッダー**（3枠）：赤いロゴ枠「ポップだるま堂／繁盛記」、日付（のこり日数）、所持金。
2. **サブバー**：次の支払いまでの日数と金額、予定収入。
3. **工房シーン**（canvasのドット絵）：詳細は第5章。
4. **ニュースバー**：最新ニュースと町の空気。タップで履歴を表示します。
   - 町の空気：いつもの町／町がざわついています／年末ラッシュ！／大にぎわい！
5. **お店の状況パネル**：
   - 左側：生産スピード（だるまピップ6個）、本日の販売数、売り逃し数、倉庫の空き、乾燥棚の空き
   - 右側：相場の3段階（安定／やや高騰／高騰）、色別の在庫
6. **色選択パネル**：あか／みどり／あお／きいろ／やめる。選択中は押し込み表示と「つくり中」の札。
7. **操作行**：素材を買う×10（価格表示、買えない理由を表示）、投資、作業スピード（❚❚ ▶ ▶▶）。
8. **フッター**：あそびかた／タイトルへ。

**レスポンシブの仕組み**
- ルートの font-size を `clamp(9px, min(1.72dvh, 3.05vw), 16px)` にし、全要素を rem で指定しています。
- `body` は `overflow:hidden`、`.app` は縦 flex と `space-between` です。
- 工房シーンは `flex:1` で伸び、上限は幅の0.82倍です。

**確認済みの画面サイズ**：390×844、375×667（どちらもスクロールなし）

**カラーパレット**
- UI：クリーム #F3E6C8、紙 #FBF1DC、墨 #2A2320、朱赤 #D8382A、オレンジ #F0782A、ミント #4FB58E、レモン #F5C742、コバルト #2F63D6
- だるまの色：あか #D8382A／みどり #3AAE78／あお #3A78D8／きいろ #F2C230

## 5. 工房シーンの描画

- **座標系**：基準は 256×176 の論理座標で、床は y=130 から始まります。
- **スケーリング**：
  - `resize()` で表示枠の縦横比に合わせて論理サイズ W×H を決めます。
  - 横長の枠では左右に、縦長の枠では上に余白を足し、内容は下揃えにします（`ox`, `oy`）。
  - canvas は `W×H × SC`（2〜5倍の整数倍）で描き、`setTransform` で論理座標のまま描画します。
- **ドット絵**：スプライトはすべて文字列の配列で定義しています（`BIG` 14×14 のだるま、`MINI` 8×8、`PERSON`／`BACK` 10×14 の人物（2倍で描画）、`ICONS` 9×9 のUIアイコン）。パレットは1文字＝1色の対応表です。
- **文字**：canvas 内の文字は DotGothic16 を論理座標で 6〜9px の大きさで `fillText` しています。
- **描画順**：背景 → のれん → ライト → 乾燥棚 → 掛け軸 → キルト → 鏡 → TV棚 → 縦看板 → 飾り棚 → 職人と作業台 → 素材 → 客とロープ → 旗飾り
- **演出**：
  - 乾燥中のだるまから湯気が出ます。乾いたのに倉庫が満杯で出せないものには赤い「!」が点滅します。
  - TVは平常時は灰色のだるま、予告中は「予告」、テレビ特需中は対象色のだるまを映します。
  - 年末は紅白の旗、インバウンド中はカラフルな旗が出ます。
  - 客は最大6人まで画面に出て、「買った！」または「売り切れ…」の吹き出しを出します。

## 6. コード構成（`<script>` 内・即時関数）

| 区分 | 主な関数・定数 | 役割 |
|---|---|---|
| 定数 | `COLORS, MM, BASE, MAT, RENT, STAFF, RACK_UP, WH_UP` | バランス調整値 |
| 状態 | `S`（全ゲーム状態）, `newGame`, `save`, `load` | 状態の管理とセーブ |
| 市場 | `marketTarget(d)`, `updateMarket()` | 相場と入荷上限 |
| 需要 | `lambda(d)`, `arrive(k, mult)` | 来客率、販売・売り逃しの処理 |
| 進行 | `step(dd)`, `newDay(nd)`, `dayNews(d)`, `showEnd()` | 時間進行、日替わり、月末、終了 |
| 操作 | `buy`, `setColor`, `setSpeed`, `openInvest`, `openHelp`, `openLog` | プレイヤーの操作 |
| UI | `renderUI`（0.25秒ごと）, `modal`, `toast`, `paintStatic` | DOMの更新 |
| 描画 | `resize`, `drawScene` と各 `draw*` 関数, `moveVisitors` | canvasの描画 |
| ループ | `loop`（requestAnimationFrame） | 経過時間 × 速度を0.01日刻みで `step` |

### セーブデータ
- localStorage のキーは `popdaruma_rt_v1` です。形式は `S` をそのまま JSON にしたものです。
- 主なフィールド：`t, day, cash, mat, fin{red,green,sky,yellow}, rack[{c,ready}], color, rackLv, whLv, staff[], recv[{amt,due}], m, sup, events[], strikes, lowMorale, stats, today, news, banner, over`
- 注意：色のキー `sky` は、表示名が「あお」になった今も互換性のためそのまま残しています。

## 7. 既知の課題・TODO候補

- **単一ファイル**：規模が大きくなってきたので、モジュール分割（sim / ui / scene / sprites / constants）とビルド環境（Vite など）の導入を推奨します。分割後もロジックは変えないこと。
- **テスト**：シミュレーション（`step` / `newDay`）がDOMに依存しているので、純粋関数に切り出すと自動プレイでのバランス検証が楽になります。
- **モックアップとの差分**：
  - 下部の富士山の装飾帯は、1画面に収めるために省略しています。
  - 日付の曜日は未実装です（「のこり日数」で代用）。
- **サウンドなし**：BGM・効果音は未実装です。
- **ダークモード**：背景色が変わるだけです。モックアップの世界観を優先しています。
- **セーブの版管理なし**：データ構造を変えるときはキーを更新するか、変換処理を追加すること。
- **バランス**：数値は暫定です。調整するときは自動プレイで「投資なし＝一人前」「投資あり＝名工」前後になるかを確認してください。

## 8. Claude Code での進め方（推奨）

1. `pop-daruma.html` をブラウザで開き、現状の動作を確認する。
2. この文書の要点を `CLAUDE.md` に転記する。特に守るべき原則は次の4つです。
   - スクロールなしで1画面に収めること
   - 操作は4種類だけ（作る色・素材を買う・投資・速度）
   - ミニゲームを入れないこと
   - トーンは昭和レトロポップ × SFC風ドット絵
3. 分割・ビルド環境の整備を最初のタスクにし、ロジックは変えずに移植する。
4. 見た目の確認は Playwright で 390×844 と 375×667 のスクリーンショットを撮り、はみ出しがないことを毎回チェックする。
